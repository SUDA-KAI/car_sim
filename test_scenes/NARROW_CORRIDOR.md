# 1.7 米直通道测试

用户现场通道净宽约 1.7 米。新增 `narrow_17` 和 `narrow_17_baseline` 两个场景，物理几何、航点和初始偏差相同，便于对比。

```bash
cd /home/a/ros2_ws/gz_sim
./run_test_scene.sh narrow_17 auto
```

启动后自动前进约 10 米，再保持车头方向倒车返回；不需要手柄或另外发送目标。在 1.7 米通道内不安排原地旋转或 U 形掉头。整轮需要几分钟，完成后窗口保留。

对照原参数：

```bash
./run_test_scene.sh narrow_17_baseline auto
```

一次只启动一个仿真，切换前 Ctrl+C 退出。需要手柄观察时把 `auto` 改为 `manual`。手柄控制不会使用 Nav2 的低速参数，前后速度仍由手柄配置决定。

## 几何与测量

- 墙体中心在 y=±0.95 米，厚 0.20 米，因此内表面是 y=±0.85 米，**物理净宽准确为 1.70 米**。
- 二维地图为 2 cm 分辨率，通道内 85 个空闲栅格，和物理宽度一致。
- 沿用 1.2 × 0.9 米的车体外廓，不缩小小车来制造“通过”。车体完全居中且车头正时，名义上每边余量 0.40 米。
- 初始位置故意偏离中心 0.10 米、朝向偏差 3°，测试能否收敛，而不只测试绝对理想的直线。
- 真值定位基准保持不变；不把定位噪声混入这次控制对照，结果不代表实车表现。

记录最大横向偏差、规划路径距离、车身矩形到侧墙的最小几何余量。余量包含朝向：

```
名义车身余量 = 0.85 - |y| - (0.6 × |sin(yaw)| + 0.45 × |cos(yaw)|)
```

此外，转向时轮胎会扫出静态 0.9 米外廓，因此另外计算轮胎扫掠的保守外包络：根据轮半径 0.2 米、胎宽 0.1 米、轮距 0.8 米和关节极限 0.75 rad，外包络最大宽约 1.146 米。这一列对所有时刻都按最大轮角处理，偏保守；没有读取真实接触传感器，不能将几何估算等同于实车安全认证。

`max_abs_center_offset_forward_settled_m` 只统计开始行驶两米之后、前进且 x≤6 米区段，避免初始故意偏移 10 cm 掩盖直行摆动。全程最大偏差同时保留，不能只看这一段指标。

## 两个版本

| 项目 | narrow_17_baseline | narrow_17 |
|---|---|---|
| TEB 前进上限 | 0.45 m/s | 0.20 m/s |
| 倒车上限 | 0.20 m/s | 0.12 m/s |
| 角速度上限 | 0.45 rad/s | 0.15 rad/s |
| 参考路径 | 原始测试权重 | 增加路径点约束、前视距离与障碍权重 |
| 平滑器 | 原参数 | 降低直线速度，减少角速度平滑造成的额外滞后 |
| Gazebo 限幅 | 原配置 | 正负公共限幅对称，具体前后速度由上层分别限制 |

Fortress 的 AckermannSteering 会把 `min_velocity/max_velocity` 同时用在线速度和角速度上。旧车模 `min_velocity=-0.2` 原意为倒车限速，却也把负角速度限为 -0.2。新版仅在 `narrow_17` 场景中改为对称的公共边界，上层 TEB/平滑器继续分别限制前后速度；其他测试场景保留，便于对照。

另外，此版本转向轮采用固定比例增益 1 的位置误差到关节速度控制，存在响应滞后。控制器、速度平滑和转向执行器的串联动态可能引起纠偏过冲。这些是已发现的影响因素，**本次修改了多项参数，不足以证明某一项就是全部摆动的单一原因，也没有宣称彻底消除摆动**。

实现依据：[Gazebo Fortress AckermannSteering 源码](https://github.com/gazebosim/gz-sim/blob/ign-gazebo6/src/systems/ackermann_steering/AckermannSteering.cc)。

## 查看结果

CSV 和 JSON 仍写到 `test_scenes/results/`。用真实轨迹单独分析包络余量：

```bash
source /opt/ros/humble/setup.bash
/usr/bin/python3 scripts/analyze_narrow_test.py \
  test_scenes/results/某次测试.csv \
  --scene test_scenes/worlds/narrow_17.json
```

对照版的 `--scene` 使用 `narrow_17_baseline.json`。输出同名前缀 `.clearance.json` 和 `.clearance.png`，包含全程轨迹、车身边界、侧墙余量以及控制指令和实际横摆速度。

低速、全新平整地图和理想定位下的结果不应直接当作真实 1.7 米通道的通过保证。实际车宽、转向轮扫掠、定位误差、墙体不平和侧滑都会消耗余量。
